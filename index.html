Memory Management Operations
● ~15 minutes

Memory management is the part of the operating system that controls how main memory (RAM) is shared between the OS and all the running processes. Every process needs space in RAM for its instructions and data before the CPU can execute it, and RAM is limited, so the OS has to decide who gets which part of memory, and when.

Why is it needed? Many processes are in memory at once. Without memory management, processes could overwrite each other's data, memory would be wasted, and there would be no way to load a new program when RAM looked full.

📋 Tracking allocation status

The OS keeps a record (a memory map or allocation table) of every block of memory: whether it is free or allocated, and which process owns it.

📏 Determining storage requirements

Before and while a process runs, the OS works out how much memory it needs — space for its code, its data, its stack and any extra memory it requests while running.

🛡️ Controlling memory usage

The OS allocates memory to processes, deallocates (frees) it when they finish, protects each process's memory from the others and moves data out of RAM when it is full.

Paging
● ~15 minutes

Paging splits memory into equal, fixed-size blocks. A process is divided into pages, and physical memory (RAM) is divided into frames of exactly the same size (for example 4 KB). Any page can be loaded into any free frame, so a process's pages do not need to be next to each other in RAM.

The OS keeps a page table for each process. It records which frame each page has been placed in, so the CPU's memory requests can be translated to the right physical location.

Benefits
  • Pages fit into any free frame, so memory is used efficiently
  • No external fragmentation — there are no awkward gaps between blocks
  • Easy for the OS to track: every block is the same size
  • Makes virtual memory possible (Section 4)
Drawbacks
  • Internal fragmentation: the last page of a process is usually only partly full, wasting space
  • Page tables take up memory themselves
  • Pages are physical divisions — a page may cut a subroutine or data structure in half
Worked example: pages are 4 KB and a process needs 13 KB. It needs 4 pages (3 pages only hold 12 KB). The 4th page holds just 1 KB, so 3 KB is wasted — that is internal fragmentation.

Segmentation
● ~15 minutes

Segmentation splits a process into logical sections called segments, which match the structure of the program — for example a code segment, a data segment and a stack segment, or one segment per module. Because they follow the program, segments are different sizes.

Each segment is loaded into one continuous area of RAM. The OS keeps a segment table giving each segment's base (its start address in RAM) and its limit (its length). An address in a program is given as a segment number plus an offset inside that segment.

Benefits
  • Segments match the program's logical structure
  • Each segment can have its own protection (e.g. code is read-only)
  • Segments such as shared library code can be shared between processes
  • No internal fragmentation — a segment is exactly as big as needed
Drawbacks
  • External fragmentation: as segments are loaded and removed, small gaps of free memory appear between them that may be too small to use
  • Harder to find space: a segment needs one continuous gap big enough to hold it
  • More complex to manage than equal-size pages
Key difference: paging divides memory physically into equal blocks; segmentation divides a program logically into meaningful, variable-size parts.

4
Virtual Memory
● ~15 minutes

Virtual memory uses part of secondary storage (an HDD or SSD) as if it were extra main memory. When RAM is full, the OS moves pages that are not currently needed out of RAM to an area of the disk (often called the swap file or page file), freeing frames for pages that are needed. This is called swapping (or paging out / paging in).

Why is it needed? It lets the computer run programs that are larger than RAM, and run more programs at once than would fit in RAM. Only the pages a process is actually using need to be in RAM at any moment.

What happens on a page fault

A page fault happens when a process tries to use a page that is in virtual memory, not in RAM. The OS then:

  1. pauses the process (it becomes blocked while the disk is read);
  2. if RAM is full, chooses a page that has not been used recently and swaps it out to disk;
  3. loads the needed page from disk into the free frame;
  4. updates the page table, then lets the process carry on.
Benefits
  • Programs bigger than RAM can run
  • More processes can be open at once
  • Cheaper than buying more RAM
Drawbacks
  • Disks are far slower than RAM, so every page fault slows things down
  • Thrashing — see below
  • Uses up disk space
Thrashing: if too many processes are running for the amount of RAM, pages are swapped in and out constantly. The computer spends more time moving pages than running programs, the disk light stays on, and everything becomes extremely slow.

Stack Frames
● ~20 minutes

Every process has an area of memory called the call stack. It is a last in, first out (LIFO) structure. Each time a subroutine (function or procedure) is called, a new stack frame is pushed onto the top of the stack. When the subroutine finishes, its frame is popped off and its memory is released.

A stack frame holds
  • the return address — where to carry on in the calling code once the subroutine ends;
  • the parameters passed to the subroutine;
  • the subroutine's local variables;
  • saved register values that must be restored afterwards.
Why is it needed?

Subroutines call other subroutines. The stack frame lets the computer remember where to return and keeps each call's variables separate, so they do not overwrite each other.

Memory for local variables is allocated automatically on a call and freed automatically on return — this is the OS and CPU controlling memory usage for you.

Python
def Square(N): return N * N def AddSquare(A, B): Result = Square(A) + B return Result def Main(): Total = AddSquare(3, 4) print(Total) # 13 Main()

When Square returns 9, its frame is popped and AddSquare continues at its return address. AddSquare then returns 13 and its frame is popped, leaving only Main.

Benefits
  • Memory is allocated and freed automatically and very quickly
  • Makes nested subroutine calls and recursion possible
  • Each call's local variables are kept separate
Drawbacks
  • The stack has a limited size
  • Very deep or never-ending recursion pushes too many frames, causing a stack overflow and the program crashes
  • Local variables are lost when the frame is popped
Recursion: each recursive call gets its own new stack frame, with its own copy of the parameters and local variables. A recursive subroutine without a working base case keeps pushing frames until the stack overflows.

✓ Summary — Topic 1.2.4: Memory Management
Operations: the OS tracks which memory is free or allocated, determines how much memory each process needs, and controls usage by allocating, freeing and protecting memory.
Paging: equal-size pages go into any free frames, tracked by a page table. No external fragmentation, but some internal fragmentation in the last page.
Segmentation: a program is split into logical, variable-size segments with a base and limit in a segment table. Good for protection and sharing, but causes external fragmentation.
Virtual memory: disk space acts as extra RAM. Lets larger and more programs run, but page faults are slow and too much swapping causes thrashing.
Stack frame: pushed onto the call stack on every subroutine call; holds the return address, parameters, local variables and saved registers; popped on return.
Stack overflow: the stack is limited in size, so very deep or endless recursion pushes too many frames and the program crashes.
